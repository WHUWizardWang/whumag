## 界面与运行选项

界面基于 Qt 5.15 的 Fusion 样式加一份 QSS 主题（`resources/theme/app.qss`），主要构成：

- 主窗口：左侧工作流导轨（数据 → 预处理 → 建图 → 评估 → 导航）、命令栏、工程面板、任务与日志面板。
- 弹出窗口：数据查询、导入数据、新建工程、一键成图、整图建模、匹配导航、数据融合等，布局与样式一致。
- 主题与强调色：菜单"视图"里切换浅色 / 深色 / 跟随系统，选择保存在 QSettings。
- 命令搜索：`Ctrl+K`。
- 文字大小以磅（pt）为单位，随 Windows 的文字缩放（125%、150% 等）一起缩放。

命令行参数：

| 参数 | 作用 |
| --- | --- |
| `--offline` | 跳过数据库登录，离线工作；依赖数据库的功能会置灰 |
| `--theme=light` / `dark` / `system` | 只对本次运行覆盖已保存的主题 |
| `--console` | （仅 Windows）打开调试控制台窗口 |

新增源码放在 `src/ui`：`thememanager`（主题）、`uiicons`（内置 SVG 图标，由 `tools/gen_ui_assets.py`
根据 `tools/ui_icons.json` 生成）、`uiwidgets` / `formkit` / `resultpreviewpanel`（各窗口共用的控件与布局块）、
`uiscale.h`（随文字缩放的尺寸）。新增 `.cpp` / `.h` 后要写进 `whumag.pro`。

### 离线地图

主界面的地图只使用本地瓦片，不联网：瓦片放在 `resources/Map/offline_tiles/<缩放级别>/<x>/<y>.png`
（标准 XYZ 瓦片目录，256×256 PNG），构建时由 `deploy_resources.bat` 复制到程序目录的 `offline_tiles`。
地图能放大到的最大级别取自该目录中最大的缩放级别文件夹；没有瓦片的区域显示为空白。
现有瓦片覆盖全球 0～5 级、中国及周边 6～8 级；需要更细或更大范围时，把对应级别的瓦片按同样的目录结构放进去即可。

### 界面自动化检查（可选）

用 `qmake "DEFINES+=WHUMAG_UI_TEST"` 构建会带上测试钩子（`src/app/uitesthooks.cpp`）。运行时设置
`WHUMAG_TEST_GRAB=<目录>`，程序会把每个可见的顶层窗口保存为 PNG 后退出；`WHUMAG_TEST_PROJECT`、
`WHUMAG_TEST_QUERY`、`WHUMAG_TEST_SHOW` 等变量用来打开工程、查询窗口或指定窗体，详见该文件的注释。
正常发布构建不要带这个宏。

## 数据导入

“导入数据”窗口选择文件后会打开“数据格式与列设置”对话框（代码在 `src/dataio`：`tableimport` 文本解析与转换，
`binarytables` 二进制格式；对话框为 `src/app/dataimportdialog`）：

- 文本（.txt / .csv / .dat / .xyz 等）：分隔符（空格、逗号、分号、制表符、竖线或自定义）、列标题、文字编码
  （UTF-8 / GBK）均可自动识别，也可手动指定；可跳过开头若干行和前几列，`#` 开头的注释行和空行自动跳过。
  数值支持科学计数法、Fortran 的 `1.0D+03`、小数逗号（分隔符不是逗号时）、半球字母（`120.5E`、`S30.2`）和度分秒（`120°30'15"E`）。
- NASA CDF 3.x（.cdf，如 Swarm、澳门科学一号等卫星磁测数据，支持 GZIP / RLE 压缩）：每个按记录存储的数值变量为一列，
  多分量变量（如 `B_NEC[3]`）拆成多列，`FILLVAL` 视为空；时间列显示为日期。
- netCDF classic（CDF-1 / CDF-2 / CDF-5，.nc / .grd / .cdf）：二维网格（如 GMT 网格）展开为 x y 值，
  航迹数据取最长维度上的一维变量；`_FillValue`、`scale_factor`、`add_offset` 会被处理。netCDF-4（HDF5）暂不支持。

在预览表每列上方选择它的含义：X（经度）、Y（纬度）、磁场值；只有矢量数据时选“分量 1、2、3”，磁场值按
√(B1²+B2²+B3²) 计算。可填写一个无效值（如 99999），含该值或无法识别为数字的行会被跳过并在日志中给出示例。
导入后工程 `Measured` 目录里保存的是统一格式的 `real_<名称>.txt`（每行 `x y 值`，空格分隔）。

## 匹配导航

代码在 `src/navigation`：`navdata`（数据类型、背景场格网、文件读写、精度）、`tercom` / `iccp` / `sitan`
（三种算法，不依赖界面）、`navigationrunner`（按所选方法串联算法并保存结果，在后台线程运行）、`navplot`（结果图）、
`navigationform`（窗口）。

输入文件每行一条记录，字段可用空格、制表符、逗号或分号分隔，空行、`#` 注释和表头会跳过：

| 文件 | 内容 |
| --- | --- |
| 背景场 | `x y 磁场值` |
| INS 航迹 | `x y 实测磁场值`（其后的列忽略） |
| 真实航迹（可选） | `x y`，与 INS 航迹逐点对应，只用于计算精度 |

窗口里的“坐标单位”（公里、米、度）说明 x、y 的单位，分辨率、TERCOM 搜索半径和误差都按这个单位显示；
选“度”时 x 为经度、y 为纬度，误差另外按当地尺度折算成米。算法本身按平面坐标计算，
经纬度数据区域较大或纬度较高时，建议先投影为平面坐标（如 UTM）。

结果写到窗口里选择的输出文件夹：`<方法>_match.txt`（每行 `x,y,实测磁场值`）、`navigation_accuracy.txt`
（各方法相对真实航迹的均方根误差，坐标单位和米各一列）和结果图 `<方法>.png`。

## 数据处理：延拓、融合、通化

代码在 `src/dataprocessing`，算法部分不依赖界面：`procgrid`（散点格网化、空洞填补、经纬度局部平面）、
`continuation`（位场延拓与 L 曲线）、`fusion`（多源数据融合）、`timecorrection`（通化）、`lcurveplot`（L 曲线图）。
输入文件每行 `x y 数值`，分隔符和 `navdata` 相同；结果只写出有数据的节点。

**延拓**（向上 / 向下 / 延拓精度评估）：散点先格网化（已是规则格网时直接使用），空洞只在 FFT 时临时填补；
四周镜像扩边并加余弦过渡，只去掉均值。勾选“BL 坐标”时经纬度按当地尺度换算成米，高度单位为 km；
否则高度与坐标同单位。向下延拓的四种算子（Tikhonov、积分迭代、Landweber、迭代 Tikhonov）的正则化参数
可以手动指定，也可以自动取 **L 曲线**拐点：在一组候选参数上计算残差范数 ‖R·f − g‖ 与解范数 ‖f‖，
在双对数坐标下取曲率最大的点，结果窗口的“L 曲线”页显示整条曲线和所选参数。
“延拓精度评估”先向上延拓再向下延拓回原高度，与原始数据比较（全区和去掉 10% 边缘的内部分别统计）。

**数据融合**：各数据源按 1/中误差² 加权，窗口内的测点按 Shepard 距离权插值到格网（窗口为全宽，
超出窗口的格网点不输出）。可选的两步检核：剔除粗差（每个测点与同一数据源最近 12 个测点的中位数比较，
阈值为 3.5 倍的稳健中误差与局部离散度中较大者）；消除系统偏差（以中误差最小的数据为基准，
取重叠区差值的中位数）。日志里给出每个数据源的偏差、剔除点数和留一交叉验证均方根。

**通化**：通化后数值 = 实测值 + F_IGRF(通化到日期) − F_IGRF(测量日期)，坐标须为经纬度（度），高度单位 km，
日期须在 IGRF-14 的 1900—2030 年范围内（2025 年以后为预测值）。IGRF 系数文件为程序目录下的
`COF/IGRF14_Windows.COF`。
